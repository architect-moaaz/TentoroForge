# 9y8de8i7 — Mobile Shell

Native Android + iOS app that hosts your deployed 9y8de8i7 web app
in a WebView. Produced by Tentoro Forge; you can build APK / AAB / IPA
files locally with the Expo CLI + EAS Build.

## What this is

A thin Expo React Native shell (`App.tsx`) that:
- Renders a full-screen `WebView` pointed at your deployed URL (default
  from `app.json` → `expo.extra.appUrl`, override with
  `EXPO_PUBLIC_APP_URL` at build time).
- Handles native chrome: safe-area insets, status bar, pull-to-refresh,
  Android hardware back → WebView history, external links open in the
  system browser, iOS swipe-back gesture.
- Ships as a signed native binary via EAS Build (cloud macOS/Linux
  runners — no local Xcode / Android SDK required).

## Prerequisites (one-time)

```bash
npm install -g eas-cli
cd mobile
npm install
eas login             # your Expo account
eas init              # links this folder to an EAS project
```

The `eas init` step writes an EAS project id back into `app.json`
(replaces ``). Keep that value — it wires future
builds to the same project.

## Build a preview APK / IPA (for UAT + local testing)

Preview builds are internal-distribution — installable APK on Android
(sideload), IPA that works on ad-hoc-registered iOS devices or the
iOS simulator. No app-store signing needed.

```bash
# Point the shell at your UAT deploy:
export EXPO_PUBLIC_APP_URL=https://your-uat-app.example.com

# Android APK — anyone with the file can sideload
npm run build:preview:android

# iOS device IPA — needs a paid Apple Developer account
npm run build:preview:ios

# iOS simulator IPA — free, runs in Xcode Simulator only
npm run build:preview:ios-sim
```

When a build finishes EAS gives you a download URL. That URL is your
APK / IPA.

## Build for the App Store / Play Store

Production builds are signed store-ready artifacts. You need:

- **iOS**: paid Apple Developer account, App Store Connect API key
  (issuer id + key id + `.p8` file) in `secrets/ascApiKey.p8`.
- **Android**: Google Play Console account, service-account JSON key
  in `credentials.json`.

```bash
export EXPO_PUBLIC_APP_URL=https://your-production-app.example.com

npm run build:production:android    # produces AAB for Play Store
npm run build:production:ios        # produces IPA for App Store

# Submit directly:
npm run submit:android
npm run submit:ios
```

## Common gotchas

- **iOS unsigned IPA is useless.** iPhones refuse to install anything
  that isn't signed with a real Apple Developer identity. Use the
  simulator profile if you don't have a paid account yet.
- **Change the bundle ID once** before your first store build. Edit
  `app.json` → `expo.ios.bundleIdentifier` and `expo.android.package`.
  The default (`com.tentoro.9y8de8i7`) is placeholder — you almost
  certainly want your own reverse-domain identifier.
- **App name + icon** are baked into the binary. To change either after
  a store submission you need a new build + a new store review.
- **The WebView is a real WebView.** Server-side rendered pages, cookies
  and localStorage all work. But: no offline mode, no push notifications
  yet (add via `expo-notifications` if you need them), no biometrics
  yet (add via `expo-local-authentication`).

## Updating the URL after publish

The deployed URL is baked in at build time via `EXPO_PUBLIC_APP_URL`.
To swap it (e.g. UAT → prod) without a new binary, use EAS Update:

```bash
eas update --branch production --message "point at new prod URL"
```

Requires configuring `expo-updates` in `app.json`; not enabled by
default in this template.

## Directory contents

- `App.tsx` — the WebView shell.
- `app.json` — Expo config (name, icon, splash, bundle ids, plugins).
- `eas.json` — build profiles (development / preview / production).
- `package.json` — dependencies + build scripts.
- `babel.config.js`, `tsconfig.json` — Expo TypeScript setup.
- `assets/` — icon, splash, favicon (regenerated by the platform each
  time you re-run generation).
- `secrets/` — App Store Connect API key (never committed).
